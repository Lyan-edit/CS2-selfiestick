# 2026-11-16 稳定性与性能审查

本次审查针对整个当前 native 运行路径以及尚未发布的 `recording-time-fix1` 工作区；不是仅检查 v0.4.8 发行包的差异。结果构建标识为 **v0.4.8 stability-audit-fix2**，保留上一轮按 Demo 渲染时间驱动的录制时序修正。未升级公开版本、未提交或发布 GitHub。

## 范围与依据

审查覆盖模块/Schema/特征码解析、实体与句柄生命周期、早期/最终相机热补丁、人物构图/偏航/视模抑制、道具出生队列/扫描/接续/爆开停留、线程/锁、诊断缓存/导出和 ImGui 软件渲染。两路只读复核分别检查安全规范与功能/性能契约，修复后再复核新增代码。

适配检查读取本机文件，没有启动、注入或控制游戏：

- CS2 1.41.9.7 / Steam build **26598758**；client 指纹 `6AF4A59C / 0298A000 / 0255AD5D`。
- HLAE **2.193.0** / AfxHookSource2 **0.42.0**。
- 32 个 Schema 偏移、特征码、人物最终回调边界、Demo tick/暂停 ABI 与渲染时间布局检查通过。

## 审查结果与修复

| 安全与实现规范审查 | 功能与性能审查 |
| --- | --- |
| **热补丁失败后仍可能写入（已修复）**：旧代码在 OpenThread / GetThreadContext 失败时继续执行 16/20 字节非原子补丁。现在打开线程、枚举未完整结束或上下文检查失败均拒绝写入；上下文忙碌时先恢复线程再有界重试。检查了失败路径的句柄清理。 | **诊断采样会等待争锁（已修复）**：旧代码先阻塞获取视模抑制锁，再尝试获取诊断 ring 锁。改为争用时立即跳过这一条诊断记录，相机继续执行。 |
| **不可读映像页会导致扫描 AV（已修复）**：旧扫描器直接读取整个 SizeOfImage。改为合并相邻可读区域、跳过未提交/NOACCESS/GUARD 页，区域内仍用 SEH 防御扫描期间的保护变化；发生异常则丢弃整个搜索结果。增加 PE 头、负偏移、空/残缺/非法 pattern 与匹配数量校验。 | **换线程重新开始人物滤波（已修复）**：旧偏航历史仅在线程 TLS 内保存。同一渲染帧在新线程回调会从 rawYaw 开始。只将偏航历史按实体完整句柄、实体地址、实体列表与 generation 共享，身体/构图 scratch 仍在线程内，身体位置与防穿模算法不变。 |
| **初始化线程句柄泄漏（已修复）**：关闭 CreateThread 成功返回的 initializer 句柄，创建失败时拒绝 DLL 加载。 | **诊断初始化数据增大 DLL（已优化）**：将 8192 项大数组的元素默认值设为全零，实际记录仍显式设置 `demoTick/renderFrame=-1`、`demoRate=1`。数组进入零初始化区，容量与 CSV 语义不变。 |
| **人物/UI 流程常驻保护不足（已加固）**：原先只有首次道具观察器安装前 PIN；现在初始化 worker 在启动 UI 和发布其他回调前就 PIN，失败直接退出。符合已有进程常驻设计。 | 未发现诊断数组、导出 worker 数或候选槽位的自然无界增长。道具扫描的软预算与短寿命捕获路径保留；滑轨预览不落盘、松手再保存的行为保留。 |

偏航共享锁内仅包含小状态比较、滤波算术和状态复制；读取引擎、实体、时钟、分配、日志与文件写入均不在该锁内。目标、会话/generation、模拟时间回退和 Demo 时间回退仍会重置历史。

预设按钮绕过模式入口的初步怀疑已撤回：当前 UI 只在人物模式提供人物预设，正常操作先经过 SetCameraMode。未为此修改 UI 或模式逻辑。

## 可复现后台测试

所有执行均为隐藏 standalone 测试进程，不加载实际 DLL 到 CS2。

1. 热补丁注入假的 Win32 API 表，不暂停真实游戏线程。旧实现遇 OpenThread 失败仍写一次，退出码 28；修复后覆盖打开线程、枚举、暂停、上下文、忙碌指令指针和写入失败，断言拒写、已暂停线程全部恢复、句柄关闭。
2. 假 PE 的中间页设为 PAGE_NOACCESS，末段放签名。旧实现稳定访问冲突退出 `0xC0000005`；新实现找到正确签名且不跨不可读间隙。另覆盖不同保护的相邻可读区边界、GUARD 页不被消费、扫描期间失去可读性、非法 PE 头与 pattern。
3. 另一个线程持有 suppression 锁时调用真实诊断生产函数。旧实现等待锁，测试失败；新实现立即丢弃诊断样本，不改变 ring 数量。
4. 真实最终相机 JIT stub 回归在量化慢速转身第 194 步，于新线程执行同一帧。旧机位差 **0.338786**、角度差 **0.385986°**；新机位/角度差均在 **0.0001** 以内。
5. 中英文完整回归通过：人物 1200 次回调、全 pawn/移动服务内存未被相机写入、原生后置改写、FOV、句柄复用、持枪/切刀、慢转/暂停/跳转、8192 项 CSV，及道具短寿命/出生事件/32768 槽/自动接续/爆开停留/锁定、1024 项 CSV 和生产 UI 涂抹回归。
6. 1200 FPS 相同录制帧配不同编码墙钟延迟的结果仍为 **0.000000°** 偏航差；上一轮录制时序修正保留。
7. Validation、DLL 依赖、`git diff --check` 通过。依赖保持静态 MSVC，不新增 D3D/DXGI/Present hook。
8. 将本机 client.dll / schemasystem.dll 以 `SEC_IMAGE_NO_EXECUTE` 只读映射，直接运行新的生产扫描器；不调用 LoadLibrary、不执行 DllMain。七种实际签名的匹配数量分别为 **1 / 1 / 2 / 1 / 1 / 1 / 1**，与独立二进制检查一致。

测试入口为 `native_dll/selfiestick_ui_preview/selfiestick_ui_preview.cpp`；新增故障注入用例在 `stability_checks.h`。`tools/Build-Native.ps1` 使用 PowerShell 7 构建。
可选实际映像检查入口为 `selfiestick_ui_preview.exe --scan-images <client.dll绝对路径> <schemasystem.dll绝对路径>`。

## 性能对照与保留范围

先记录工作区基线，再从改动前源码备份独立重建旧 EXE，交替运行 before/after 各三轮，避免仅拿不同负载时的一次最大值对比。下表为三轮对应统计量的中位数，单位 ms：

| 后台路径 | before median | after median | before P95 | after P95 |
| --- | ---: | ---: | ---: | ---: |
| 人物完整相机回调，1200 次 | 0.003 | 0.003 | 0.003 | 0.003 |
| 道具扫描，32768 个填充槽、500 次 | 0.290 | 0.295 | 0.380 | 0.367 |

扫描耗时存在后台调度波动；三轮 after median 范围 0.294–0.314，before 为 0.290–0.292。道具扫描源码没有修改。这组微基准没有显示明显性能回退，但不能据此保证游戏 FPS、1200 FPS 实录或所有插件组合零回退。详细输出及 JSON 留在忽略目录 `dist/stability-audit-2026-11-16/`。

中文本地 DLL 从 **2,892,288 → 1,191,936 字节**，英文从 **2,889,728 → 1,189,376 字节**。主要减少磁盘初始化数据，诊断运行时容量仍为人物 8192 / 道具 1024；不是删除诊断功能或减少实体扫描来换取指标。

确认稳定部分的 12 项保护清单全部通过。相对本轮改动前源码，道具 discovery/view/clock/lifecycle/diagnostics 五个文件、player_frame.inl、player_view.inl 和 setup_view_hook.cpp 均逐字节不变；身体高度/绝对原点/机位安全距离与道具已确认的稳定机位算法保留。
