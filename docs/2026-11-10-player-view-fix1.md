# 人物自拍机位切换与刷新卡顿修复 — 2026-11-10

本地构建：`v0.4.6 player-view-fix1`。支持 CS2 build `26445667` / HLAE `2.192.10`。
GitHub 既有 v0.4.6 Release、源码标签和发行附件没有修改；仓库首页设计也保持原样。

## 复现与判断

用户提供的截图显示原生第一人称武器画面与人物外部机位交替。截图不能证明每一帧的调用来源；本次检查没有启动或注入 CS2，已有本机日志也不是本次症状的实时记录。

检查生产路径发现：

1. 道具路径已经通过引擎绝对坐标 getter 处理脏场景变换；人物眼位校验却先复制原始缓存，再调用 render-eye。旧缓存与新眼位可能不在同一更新状态，合法眼位可能被拒绝，回退构图也可能使用过期坐标。
2. 人物构图失败就退出 SetUpView 覆写并恢复武器显示；下一帧成功再隐藏。它与完整道具机位的恢复策略不同，可能在原生／自拍视角与模型状态之间反复切换。
3. 手部和角度缓存在 0.25 秒墙钟后失效，暂停／慢放期间可能切换构图基准；缺失武器元数据也会触发模型显示状态恢复。
4. 附件 getter 的输出此前初始化为零；若它返回成功但没有完整写出坐标，零／部分输出可能被误当成有效位置。

新增真实生产函数回归模拟“眼位与骨骼已经更新、原点缓存仍脏”：**修改前第 0 帧瞄准点偏差 80.000 单位，退出码 26**。修改后 480 次 ±80 单位过期缓存交替均使用引擎重算后的坐标。

## 修改

- `player_frame.inl` 只服务人物路径，复用已验证的绝对坐标 getter，再校验并记录探员局部眼位。render-eye 临时未写出时保留同一探员的眼位高度，避免站立／蹲下高度反复切换。
- 手部附件缺失时保留同一有效探员的最后局部手位和朝向，继续随探员原点移动；没有可靠手位的冷启动才使用身体相对位置。不会因为墙钟超过 0.25 秒而切换基准。失败附件查询最多每 50 ms 重试一次，正常坐标和有效附件仍逐回调更新，没有 sleep 或阻塞等待。
- `player_view.inl` 保留同一有效探员的完整构图。场景／眼位暂缺时继续使用上次有效自拍机位，不立即退回原生第一人称。真实实体失效或句柄序列变化不允许借用旧机位。
- 观战来源的刷新临时失败时，仅在 0.25 秒内、旧探员仍通过完整句柄验证的情况下保留目标。明确观测到新探员立即切换；超时或旧实体失效则停止保留。
- 武器元数据或实体列表项暂缺时保留已验证的模型隐藏状态与原始恢复值。确实切到另一件武器或关闭自拍时仍按完整句柄安全恢复，不通过旧裸指针写入。机位恢复或元数据缺失时保留最后有效 FOV；正常完整采样仍使用原有 AWP 处理。
- 缓存按探员句柄、实体指针、实体系统和启用／模式／目标选择代次隔离；模拟时间回退超过 0.25 秒也使旧构图失效。
- 附件输出改用 NaN 哨兵，拒绝未写出、部分写出和非有限坐标。

同一有效探员持续缺少完整坐标时会保留已有机位，直到数据恢复或用户关闭／更换目标。冷启动无可靠机位、实体已失效等情况仍保留游戏原生视角，不猜测错误世界坐标。未增加地图碰撞避让。
