# 人物身体固定机位 — 2026-11-10

本地构建 `v0.4.6 player-body-fix2`；CS2 build `26445667` / HLAE `2.192.10`。
GitHub 正式版附件未替换，个人 INI 保留。

## fix1 遗漏的情况

用户反馈 fix1 仍有反复抽搐和穿模，怀疑持枪动画带动手臂机位。源码确认：即使读取成功，fix1 仍逐帧使用 `weapon_hand_r` 动画后的世界坐标；有效的手部动画和 render-eye 偏移都可以带动机位。上一轮主要模拟数据缺失，没有覆盖这种有效动画。

新增用例始终返回有效手部、眼位和原点，仅让手位和眼位按周期变化。fix1 第 1 个动画样本的锚点移动 **5.164 单位**，用例失败（退出码 26）。这证明该耦合存在，但不能仅凭截图断定它是实机症状的唯一来源。

## 新机位

- 人物锚点改为探员身体固定局部位置：引擎重算后的身体原点，加上由探员偏航构建的右／前／世界上方向与固定偏移。不再读取手部附件和 render-eye 来决定人物位置或瞄准点。
- 身体参考高度使用 `64 - 18 * duckAmount`，跟随合法下蹲过渡。新增的两个 class-qualified 字段已从当前 client.dll 的 schema 表离线核实：`C_BasePlayerPawn::m_pMovementServices = 0x1330`、`CCSPlayer_MovementServices::m_flDuckAmount = 0x40C`。生产端仍要求精确版本，不做运行时 TypeScope 探测。字段暂缺保留同一探员最后有效高度；冷启动用 64。
- 构图只随身体移动、玩家偏航和下蹲变化。武器种类、换枪、切刀、换弹、有效手位抖动及动画眼位不再改变人物位置或瞄准点。左右自拍、越肩、R/B/U 和角度微调继续使用原有预设。
- 增加身体附近最小水平间距：自拍 32 单位、越肩 24 单位。过近微调被推回该半径；自拍瞄准点随修正后的相机重新计算。它是防贴入探员身体的距离约束，**不是地图墙体碰撞检测，也不保证所有伸出的枪械／肢体几何永远不与镜头相交**。
- 保留 fix1 的场景暂缺保留机位、FOV 恢复、模型显示原值保全、完整句柄验证与 Demo 回退失效处理。运行状态和成功日志的玩家锚点改为 `pawn_body`。

## 人物诊断

人物模式下展开“运行状态”，点击“导出抖动诊断”，在加载 DLL 的目录生成 **`selfiestick_player_motion.csv`**。道具模式仍导出原来的道具诊断。

人物采样最多保留 1,024 条，记录版本、预期／实际目标句柄、武器句柄、身体原点、固定锚点、瞄准点、本 DLL 回调输出的相机位置／角度、FOV、恢复／隐藏状态和结果。结果 0=无目标，1=无完整机位，2=已覆写。没有实体指针或玩家姓名。

相机回调只尝试写入固定内存环，不写文件；显式点击导出才启动单一后台写文件线程。该 CSV 表示本 DLL 回调时的状态，不能直接观测 GPU 最终画面或其它插件在后续阶段的改动，可用于区分“本 DLL 机位发生跳变”和“机位稳定但仍有第一人称模型异常”。

## 验证

- 修改后 600 次有效手部／眼位动画扰动不再改变锚点或瞄准点；20 组移动、转身和连续下蹲仍正常改变身体机位。
- 中英文各 1,200 次完整生产 SetUpView 回调，覆盖有效动画、场景暂缺、元数据和 FOV 缺失；人物骨骼及 render-eye 查询次数均为 **0**。极端 R/B/U 的水平间距、左右自拍和越肩通过。
- 切刀、关闭恢复、冷启动失败、句柄复用、观战来源刷新和 Demo 回退用例继续通过。
- CSV 独立解析确认每版 1,024 行、25 列、序号严格递增，含成功／失败回调及正确 build 标识；只在显式导出时产生文件。
- 已安装 CS2 的特征码、**32 个 schema 字段**、眼位虚表／出生监听／绝对坐标访问器通过；PowerShell 7 中英文 x64 `/MT` 构建、原生验证、两版依赖审计和 ImGui framebuffer 检查通过。
- 道具 fix5 的 **12 个受保护区段**哈希一致，**5 个 prop_*.inl 运行时文件逐字节未变**，既有道具跟随、2 秒 Demo 停留、锁定和诊断回归通过。
- 假实体全回调测量中位数约 0.001 ms、p95 0.002–0.003 ms。不能视为真实游戏 FPS 或真实引擎坐标计算开销。

本次仍仅后台验证，没有启动、注入、前台操作游戏或进行实机 Demo／ReShade／帧率测量。新身体机位是否完全消除用户当前症状仍需实机验收。
