# MulNX_CS2-Beta17 人物相机对比及 HLAE 2.193.0 核查

日期：2026-11-11。结论：**有可借鉴的设计，但直接替换为 Beta17 的人物自拍实现，不能可靠解决现有转身／切刀抽搐，且可能重新引入跳变和穿模。**

本次读取工作区 `E:/codex项目/codex-自拍杆/MulNX_CS2-Beta17` 实际源码，没有以先前评审的其它提交代替 Beta17。未运行 MulNX DLL、未启动或操作 CS2、未替换当前 fix4 DLL。分析工具仅进行文件读取与数学模型计算。

## 核心差异

| 环节 | 本地 Beta17 | 当前 player-final-view-fix4 | 对本次问题的判断 |
| --- | --- | --- | --- |
| 几何来源 | 武器三骨骼／人体三骨骼二选一；默认武器；另有头模式使用输入 CViewSetup | 探员身体绝对原点、下蹲高度和仅偏航的身体局部坐标系，武器只提供可选元数据 | 人体来源值得参考；恢复武器或手臂动画绑定会重新让切刀／开枪动画移动相机 |

### 1. 同 tick 跳过写入是明确风险

`AdvancedViewController.cpp:84` 的条件使用 `TimeController::GetTime()`；后者在 `TimeController.cpp:94` 直接返回整数 Demo tick / 64。条件不满足时直接 return false，尚未写回相机；没有在这个模块里重新输出上一次自拍位姿。`AlwaysCaulate` 可以绕过条件，但默认是 false。

独立模型使用源码可见的条件，模拟 10 秒、144 FPS、成功计算、单一视角控制器：

| Demo 倍率 | 回调数 | 自拍写入数 | 跳过写入数 |
| --- | ---: | ---: | ---: |
| 0.01x | 1440 | 6 | 1434 |
| 0.1x | 1440 | 63 | 1377 |
| 1x | 1440 | 639 | 801 |

0.1x 的约 95.6% 回调不会由这个模块写入自拍相机。如果原生每次提供新的观战位姿、且没有其它模块补写，就可能在观战与自拍之间跳。这是从源码与模型推导的风险，**不是 MulNX 实机录制结果**；开启 AlwaysCaulate、额外平滑或其它视角模块会改变其表现。

### 2. 不能直接平滑整台相机的世界坐标

`ViewSmoother.cpp:5` 对世界 XYZ 插值；`ViewSmoother.hpp` 的默认系数是 0.2，每次回调使用相同系数，未按帧时长或 Demo 倍率换算。其输入来自此前各模块写入后的 CViewSetup；如果前级同 tick 不写，平滑器可能在原生观战和自拍两种输入之间平滑。

示例：身体位于 x=0，相机从 x=48 转到 x=-48，两端都离身体 48 单位。线性平滑输出依次为 48、28.8、13.44、1.152、-8.6784，路径穿过身体附近。当前人体间距保护为 32 单位，直接接这种末端世界坐标滤波会破坏这个保护。

相同 0.2 系数对应的现实时间常数约为 30 FPS 下 149 ms、144 FPS 下 31 ms、500 FPS 下 9 ms，手感随帧率变化。该例说明需要保持身体局部半径、按时间处理方向，不是证明所有真实转身都会发生这种轨迹。

### 3. 人体骨骼有参考价值，不能等同于无抖动

`AdvancedViewController.cpp:161` 附近明确选择人体或武器，不自动回退；人体模式可绕开武器实体重建。但 `tree.cpp:4` 直接读骨骼数组的世界位置，没有在这里重建骨骼、保证其采样阶段，或实现相机身体间距保护。人体手臂骨骼仍会受拔刀／开枪动画影响；固定 0/1/2 也不能当作跨模型的稳定手臂语义。

当前 `selfiestick_hlae.cpp:6287` 和 `:6580` 已让人物几何脱离枪／刀与手臂动画；切刀只改变可选元数据。仅凭“切刀时抖”不能认定当前几何仍绑在刀上。需要继续区分实际加载版本、输入姿态更新、不同回调线程的历史以及后续视角改写。

### 4. Hook 位点实测匹配

只读扫描当前 client.dll，Beta17 的 `Pos_ClientModeCSNormal_CallIsPlayingDemo` 特征码唯一命中 RVA `0xB9E67E`，与本项目原早期入口相同。它位于原生 SetUpView 函数 `0xB9E390..0xB9EACC` 内，后面仍有原生视角处理。当前 fix4 的人物覆写在 RVA `0xB9EA60`，最终历史保存之前，边界检查本次再次通过。

因此 Beta17 并没有一个能替代 fix4 的、更靠后的 Hook；其位置／角度独立计算及四元数旋转也不能阻止后续原生代码改写输出。

## HLAE 2.193.0

工作区 `hlae_2_193/HLAE.exe` 文件版本为 2.193.0.0，附带 AfxHookSource2 更新记录为 0.42.0。与官方 [v2.193.0 发布说明](https://github.com/advancedfx/advancedfx/releases/tag/v2.193.0) 一致。

通过 GitHub 连接器读取官方 v2.193.0 源码，与先前保存的 v2.192.10 比较：

- `HookClientDll` 函数逐字相同，16 字节相机入口 patch 格式没有变化，仍属于当前解码器支持的格式。
- `CS2_Client_CSetupView_Trampoline_IsPlayingDemo` 函数逐字相同，关键 origin/angles/FOV 偏移未改变。
- `MirvTime::interpolation_amount_get` 的实质修改是把 Globals 的读取偏移从 14 字节改为 14 × 4 = 56 字节，见[官方 MirvTime.cpp](https://github.com/advancedfx/advancedfx/blob/v2.193.0/AfxHookSource2/MirvTime.cpp)。旧偏移不能用于新实现。

当前自拍杆人物时钟读取 Demo tick／暂停状态，并从墙钟间隔估计播放倍率；没有调用 HLAE 的这个插值函数，也未直接读取该 Globals 偏移。**升级 HLAE 修复了其自身的插值读取，但不等于已经修复本项目的姿态采样和输出顺序。**

本次静态核查未发现 HLAE 2.193.0 相机入口与当前串接方式的新不匹配；这不等于已实机验证 2.193.0 的所有录制／预览组合。HLAE x64/AfxHookSource2.dll SHA-256：`ADD5EA80347819296EB4C9C80A67955683689AC6F4F32D695EC7EA28A1DC1A0F`。

安装版 CS2 为 1.41.9.6 / Steam build 26445667，client 指纹仍是 `6AEBC4DA / 029A3000 / 0256CDA1`。32 个 schema 字段、相机相关特征码和访问器、Demo 时钟槽 69/3/12 本次只读校验通过。

## 对当前问题最有价值的后续方向

1. 保留已确认不穿模的身体原点和间距保护、fix4 最后阶段写入、与道具的隔离。Beta17 的武器三点、跳过写入和世界 XYZ 平滑不作为替代方案。
2. 借鉴“采样、构图、输出分开”的组织方式：可减少同一渲染帧的重复采样，但每个需要覆写的回调都必须写回同一有效位姿，而不是跳过写入。
3. 优先验证连续渲染时间／子 tick 与人物姿态的同阶段采样。当前仍读取 m_angEyeAngles、用整数 tick 间隔估计速率；这与 Beta17 直接读骨骼的时间语义不同。使用插值分数前需要验证 Globals 指针、偏移、暂停和跳转，不能只复制 +56 的常量。
4. 若实机 CSV 显示不同 thread_id 的偏航历史交替，应将人物完整位姿按探员和渲染帧统一发布。当前 FOV 已共享，身体构图／偏航缓存仍为 thread_local；这是需要验证的风险，不是本次已证明的根因。

仍缺少出现问题时的实际人物 CSV，因此不能把骨骼、线程历史或插值中的任何一项宣称为已确认的唯一根因。Beta17 的源码能够排除若干不合适的移植方向，但不能替代实机输出证据。
